# سجل القرارات المعمارية والتنفيذية المتخذة بموجب التفويض (ADRs)

| الرمز | القرار المتخذ | البدائل المدروسة | مبرر الاختيار (الأدلة والمعايير) | الأثر المتوقع |
| :--- | :--- | :--- | :--- | :--- |
| **ADR-01** | اعتماد **C# (.NET 8) + PostgreSQL 16** كنواة خلفية مع **Flutter + SQLCipher** للعميل وتأجيل **Python** لخدمة AI في المرحلة 3. | Python FastAPI وحده / Java Spring Boot / Go. | `decimal` 128-bit، أنماط ثابتة Static Typing، SignalR مدمج، Hangfire للمؤقتات، و`NUMERIC(18,4)` مع RLS. | تقليل أخطاء المنطق قبل التشغيل وتحمل آلاف الاتصالات المتزامنة بكلفة خوادم أقل. |
| **ADR-02** | اعتماد **حوكمة الميزات ثلاثية المستويات (25 ميزة)** وإبقاء ميزات المرحلتين 2 و3 مقفلة (`LOCKED OFF`) والوحدات المتقدمة للمرحلة 1 بحالة `OFF` افتراضياً. | تفعيل كل الميزات للجميع / حذف كود المستقبل. | حماية التاجر الصغير من التعقيد، والامتثال لبند 2.1 لـ Apple، وفرض `[RequireFeature]` على الخادم. | تطبيق واحد يتكيّف من البقالة والموزع حتى المول متعدد الكاشيرات. |
| **ADR-03** | اعتماد **بوابة التمرير بالتفويض المسبق (`Authorize & Capture`)** بدلاً من المحفظة الداخلية في المرحلتين 1 و2. | محفظة احتفاظ بالأموال منذ اليوم الأول. | تجنب متطلبات ترخيص EMI/PSP ورأس المال والرقابة المصرفية قبل إثبات السوق. | تحقيق ضمان P2P لمعاينة البضاعة دون حيازة أموال العملاء. |
| **ADR-04** | فرض **عدم قابلية القيود وتقارير Z-Report وسجل الصوت والتدقيق للتعديل (`Immutable`)** مع توثيق `SHA-256`. | السماح بالتعديل والحذف المباشر. | ضمان دقة `0.0000` ومنع التلاعب وقابلية إعادة الاحتساب الكامل من الحركات الأصلية. | سجل تدقيق جنائي ومحاسبي متكامل. |
| **ADR-05** | إغلاق عيوب `v1.2` الحرجة (`DEF-001..009`) في `v1.4` وتوحيد `v1.5..v1.7` مع إصلاح `DEF-201..209` في `v2.0`. | تسليم حزم متفرقة دون فحص تجميع. | كشف التدقيق الفعلي ثغرات BOLA ونقص فهارس الذروة (`100x+`) وأخطاء `.csproj`. | توحيد المعمارية وإزالة أخطاء التجميع الأولية. |
| **ADR-06** | تنفيذ تدقيق إنتاجي عميق للنسخة `v2.0` وإصدار **`Mizan_Production_Pilot_v2.1`** لإغلاق 8 عوائق تشغيلية حرجة (`DEF-301..308`). | بدء النشر المحلي مباشرة بـ `v2.0`. | كشف التدقيق في `v2.0`: غياب `AuthController` و`OrganizationsController`، وتضارب PascalCase في EF Core مع `snake_case` في PostgreSQL، ونقص `BaseDebit/BaseCredit` في `JournalLine` مقابل قيد Migration 005، وتجاوز السوبر يوزر لسياسات RLS، وبقاء نقاط نهاية تجريبية، وخطأ اقتطاع `NavigationBar.take(5)` في Flutter، وغياب سكربتات الشهادات والنشر المحلي. | إزالة آخر العوائق الحقيقية أمام الإقلاع الفوري على خادم المدينة المحلي وتوفير رفيق تشغيل ميداني أوفلاين (HTML/A4) لليوم الأول. |
| **ADR-07** | تنفيذ تدقيق مطابقة صارم بين EF Core ومخطط PostgreSQL `001`–`010` وإصدار **`Mizan_Production_Ready_v2.2`** لإغلاق 7 عيوب تشغيلية حرجة (`DEF-401..407`). | تشغيل `v2.1` مباشرة على PostgreSQL 16 دون فحص مطابقة الأعمدة والـ Enums والـ RLS الفارغ. | اكتشاف أخطاء محتمة عند أول استعلام فعلي: خطأ `22P02` عند تحويل سلسلة فارغة إلى UUID في RLS، تحويل EF Core للـ Enums إلى أرقام بدل نصوص PostgreSQL، تعارض أسماء أعمدة في 8 جداول، خطأ FK على `journal_entries.created_by`، عدم حفظ طبقات FIFO في القاعدة، ونقص تدوير Refresh Token واسم المستخدم الخاطئ في سكربت النسخ الاحتياطي. | إثبات تطابق 100% عبر المدقق الآلي `08_efcore_pg_schema_parity_audit.py` لجميع الكيانات الـ 15 والـ Enums الـ 15 والسياسات الـ 22 قبل الإطلاق المحلي. |
